Architecture

How it fits

Every click in the lab went through one service, bnk-inference-adapter. It owns the Inference Gateway API, turns each call into Gateway API, Gateway API Inference Extension (GAIE) and BNK objects, and collects per-request usage records that the BNK iRule sends it. One Helm chart installs it. Two small helpers sit next to it: frontier-proxy for Amazon Bedrock and calypso-relay for F5 AI Guardrails.

Production split

Who owns what

Everything the lab did, sorted by who runs it in production.

Lambda side

  • API gateway: route /api/v1/inference-* and /api/v1/network-firewall-* to the adapter on :8080, after Lambda's own key check
  • Key service that answers the introspection contract
  • Instance inventory: model-server pods or relays labelled lambda.ai/instance and lambda.ai/role, and the instance list
  • Billing pipeline reading the usage records
  • Console section built on the contract (the lab portal is the reference UI)
  • AWS account for frontier models, and the Calypso project for guardrails

Adapter side (Helm chart)

  • bnk-inference-adapter: owns the contract, renders Gateway API, GAIE and BNK objects, collects usage and firewall events
  • frontier-proxy: OpenAI-compatible front for Bedrock
  • calypso-relay: holds the guardrail token, so the iRule sideband stays plain HTTP to an IP
  • RBAC scoped to lambda-ie and f5-bnk, NetworkPolicy, a 200Mi PVC
  • Values: VIP range, sideband URLs as ClusterIPs, prices, the usage flush token

BNK side (unchanged)

  • BNK 2.4 with the Gateway API and GAIE CRDs
  • GatewayClass f5-gateway-class for the CNEInstance
  • lambda-ie in CNEInstance.spec.eppNamespaces
  • F5 registry pull secret copied into lambda-ie
  • A routable VIP range for endpoint addresses

The iRule has no DNS and no TLS

BNK iRules open sidebands as plain TCP to an IP. Give the introspection and guardrail URLs as http://<ClusterIP>:<port>/path, the form the lab ran. The target must speak plain HTTP and be reachable from TMM. Anything HTTPS gets a small relay in the cluster, which is why calypso-relay and frontier-proxy exist.

The Kubernetes objects are the truth

The adapter keeps no data-path state. Gateways, routes, pools and iRules are the state of every endpoint. SQLite holds only policy config, usage records and benchmark runs. Delete endpoints through the API, and never uninstall the chart with endpoints still running.

OpenAPI 3.1

The contract

There are two contracts, one per API. The Inference API covers endpoints, policies, usage and benchmarks. The Network firewall API covers policies, address and port lists, log destinations and events. Both are proposed extensions of the Lambda Cloud API v1.10.0 and follow its conventions on purpose, so they can sit in the same spec:

  • Resources under /api/v1/inference-endpoints, actions under /api/v1/inference-endpoint-operations/…. That's the same split as instances and instance-operations.
  • Every response is wrapped in {"data": …} and every error in {"error": {"code", "message", "suggestion"}}, using Lambda's codes (global/invalid-api-key, global/object-does-not-exist, global/invalid-parameters).
  • Bearer keys come from the same API keys page.

The one addition outside that pattern is PATCH …/policies/{kind}. BNK enforces enabled policies in the data path in a fixed order: api_auth → guardrails → token_quota → ai_load_balancing.

Policy kinds

ai_load_balancing, token_quota, guardrails, api_auth, model_schedule, network_firewall. Each moves through off → applying → on (or error with a reason).

Chat outcomes

served, downgraded, auth_rejected, guardrail_blocked, quota_blocked, error. Gateway refusals come back as results with 200, not as API errors.

What BNK does

Gateways, iRules and NetPolicies live in namespace f5-bnk. Routes, Services, InferencePools and F5EPPs live in lambda-ie. Every object is labelled lambda.ai/endpoint=<id> and app.kubernetes.io/managed-by=bnk-inference-adapter, so one label selector finds everything an endpoint owns.

Auth in the lab

The browser never holds a key. The console's nginx injects one server-side, only for same-origin requests that carry X-Lambda-Console: 1 and no Authorization header. A cross-site page can't send the custom header without a preflight, which nginx never approves.

Auth in production

Use the console's existing session. Whatever your API gateway turns it into, the adapter introspects the key and needs the right sub and role back.

Types

Generate with npx openapi-typescript contracts/inference-gateway.openapi.yaml. Gateway refusals in chat (auth_rejected, guardrail_blocked, quota_blocked) are 200 results, so show them as outcomes, not errors.

Backups

Snapshot the PVC. The reconcile loop keeps cluster objects in line with the stored policy config, so a restored volume brings endpoints back to their last configuration.

Upgrades

helm upgrade with a new image. The API is down for a few seconds (one replica, Recreate). The data path isn't, because BNK keeps serving what's already applied.

Removing it

Delete every endpoint through the API, then helm uninstall. The adapter removes its Gateways, routes, pools and iRules. Nothing else will.
